# Data Dictionary

Source: `data/raw/ecommerce_retail_transactions_raw.csv` — "Messy E-Commerce Sales Dataset
2026" by AfaqKhan, Kaggle, CC0. Synthetic, 12,180 rows × 13 columns. Cleaned output:
`data/processed/clean.csv` (regenerated by `uv run messy-data-eda`, not committed).

## Raw → clean columns

| Column | Type | Meaning | Cleaning applied |
|---|---|---|---|
| `Order_ID` | string | Unique order identifier | None — used to confirm duplicate rows share an id before dropping them |
| `Customer_ID` | string | Unique customer identifier | None |
| `Order_Date` | string → datetime64 | Date the order was placed | Normalized from 5 raw formats (`YYYY-MM-DD`, `MM-DD-YYYY`, `DD/MM/YYYY`, `YYYY/MM/DD`, `DD Mon YYYY`) to a single datetime column |
| `Product_Category` | string | One of 8 product categories | None — already consistent |
| `Product_Name` | string | Free-text product name | None |
| `Quantity` | int | Units ordered | Unchanged; `Invalid_Quantity` flag added instead of dropping or clamping |
| `Unit_Price_USD` | float | Price per unit, USD | None |
| `Discount_Percent` | float (nullable) | Discount applied, one of {0, 5, 10, 15, 20, 25} or missing | Unchanged; `Discount_Missing` flag added instead of imputing |
| `Payment_Method` | string | Payment method used | Standardized from 20 raw spellings to 6 canonical labels (`PayPal`, `Net Banking`, `UPI`, `Debit Card`, `Cash on Delivery`, `Credit Card`) |
| `Shipping_City` | string (nullable) | Delivery city | Missing values filled with `"Unknown"`; `City_Missing` flag added |
| `Country` | string | Customer's country | Standardized from 24 raw spellings/abbreviations to 7 canonical country names |
| `Order_Status` | string | One of Delivered/Shipped/Pending/Cancelled/Returned | None — already consistent |
| `Customer_Rating` | float (nullable) | 1–5 star rating | Left untouched — NaN is a real state, not a defect (see below) |

## Columns added during cleaning

| Column | Type | Meaning |
|---|---|---|
| `Invalid_Quantity` | bool | `True` if `Quantity <= 0` — a data-entry error, excluded from quantity/revenue aggregates but not dropped from the dataset |
| `Discount_Missing` | bool | `True` if `Discount_Percent` was NaN before cleaning |
| `City_Missing` | bool | `True` if `Shipping_City` was NaN before cleaning (now filled `"Unknown"`) |

Exact duplicate rows (180 of them — see `reports/quality_report.md`) are dropped entirely
during cleaning and have no representation in the clean dataset.

## Why `Customer_Rating` is never imputed

100% of Cancelled/Pending/Returned/Shipped orders have no rating — an order that was never
delivered cannot be rated. Of Delivered orders, 643/6,673 (9.6%) also lack a rating, a real
"customer didn't leave feedback" gap. Both are legitimate absences, not data-quality defects,
so `Customer_Rating` stays `NaN` and every EDA function that uses it drops nulls explicitly
rather than treating them as zero.
